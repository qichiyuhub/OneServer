# OneServer 长期决策与踩坑

本文件记录仍约束当前实现、或很容易被误判为 bug 的设计。编号保持与源代码注释兼容，可稀疏；已不再有影响力的阶段记录、会话日志和完成清单不保留。需要变更某项结论时，同时更新实现、测试和本文件。

## 架构、执行与安全

| 编号 | 结论 | 原因与后续约束 |
|---|---|---|
| D2 | 先建立框架和可验证规范，再迁移功能。 | 不以 lint 豁免或旧实现替代工程约束；新代码不得加入豁免表。 |
| D5 | 运行时零额外依赖。 | 最小系统未必有 `jq` 等工具；库与脚本以 Bash/coreutils 和已声明的系统工具实现。 |
| D8 | 注册表是命令发现的单一事实源。 | CLI、菜单与补全均由元数据派生；新增命令不应修改前端。 |
| D9 | “有副作用且需读取输出”是独立执行类别。 | 必须用 `os::run_out`，不能以只读 query 绕过 dry-run。 |
| D10 | 同一系统事实只能有一个 probe 实现。 | 多消费者需求进入 `probe.sh`，避免不同界面给出矛盾结论。 |
| D14 | 命令派发和更新切换必须 `exec`。 | 避免父进程继续从被替换的脚本读取字节。 |
| D15 | 会谎报成功的 dry-run 比没有更危险。 | 通过 `OS_RUN_SKIPPED` 区分跳过与无输出；预演不产生变更。 |
| D18 | probe/query 必须有超时。 | 菜单和诊断不能因挂起的服务、挂载或 Podman 永久阻塞。 |
| D23 | 锁放 `/run/oneserver`，不放 `/tmp`。 | 防止 root 跟随攻击者预置的符号链接。 |
| D25 | 不提供可覆盖的路径配置。 | root 进程路径不能被外部环境或配置改变。 |
| D26 | 不缓存注册表。 | 少量脚本扫描成本低，缓存会静默过期。 |
| D27 | 使用单一全局锁。 | apt、Podman 已有自身串行机制；分域锁只引入顺序和死锁风险。 |
| D28 | 不为尚无稳定产品边界的容器能力设计接口。 | 不把薄封装或未验证接口写入支持面。 |
| D32 | 菜单编号按屏重排 1..N；`@order` 只决定排序，不上屏。 | 一个字段兼任「排序权重」与「屏幕上的选择键」的代价是：二级菜单打的是 51..55，虚拟项「备份与恢复」编号 38 而它的成员是 33/34，同一次操作连按三层看到 25 → 51 → 1。编号改为每屏从 1 数起后，`@order` 收窄成**组内**唯一（见 D221），只服务于排序；顶层直接敲子条目编号的旧路径随之删除，改由输入命令名直达（`registry::resolve` 最长前缀）。 |
| D33 | 脱敏按值而非参数位置。 | 位置变动会静默泄密；短凭据值拒绝作为脱敏值。 |
| D35 | 组件标识为 `<type>[:<instance>]`。 | state、依赖、unit 和卸载都使用完整标识，支持多实例。 |
| D36 | unit 必须标记 `own:` 或 `ext:`。 | 外部软件包的 unit 只能停止/禁用，绝不删除其文件。 |
| D39 | state 使用行式格式，JSON 仅用于输出。 | 不依赖 jq，局部损坏不应让全部 state 无法恢复。 |
| D40 | 信号中断不执行回滚栈，退出 131。 | 中断时系统状态未知；临界区保护无法安全中断的序列。 |
| D44 | probe 的实时/缓存来源和时间必须可见。 | 非 root 不能把旧快照伪装为实时事实。 |
| D47 | CI 规则须区分完备检查与启发式检查。 | 不能把无法静态判定的规则伪装成完整保证。 |
| D46 | 菜单分组是 `groups.conf` 中的产品数据。 | 添加或改名分组不应改变框架规范；注册表校验脚本引用。 |
| D51 | 配置 key 与 L0 变量同名。 | 白名单由现有变量自然形成，避免维护第二张映射表。 |
| D53 | 配置加载和校验属于 bootstrap。 | L0 只能含常量；校验需在 L1 初始化之前完成。 |
| D56 | lib 模块不互相 source。 | bootstrap 和测试辅助是唯一明确装配路径。 |
| D57 | warn/error 默认走 stderr。 | 使正确输出流成为默认，避免失败信息被日志重定向吞掉。 |
| D59 | `log.sh` 属于 L1。 | `errors.sh` 需要单向依赖日志，不能用同层依赖破例。 |
| D62 | `exec.sh` 属于 L2。 | probe、systemd 与模板能力都需要它；下沉可避免 L3 同层依赖。 |
| D63 | `--env` 通过子 shell export 后 exec。 | `env K=V command` 会把秘密暴露在 argv。 |
| D64 | 命令自身输出也必须先脱敏再写日志。 | token、连接串可能由命令回显，不只来自框架命令行。 |
| D65 | SQL 客户端显式设置字符集。 | Ubuntu/MariaDB 组合可能静默损坏四字节字符。 |
| D68 | probe 不打印返回值。 | 通过变量返回以保留来源、年龄和状态，避免命令替换子 shell。 |
| D69 | `systemd.sh` 收集 touched unit，由 L4 落 state。 | 保持 L3 模块无同层依赖。 |
| D70 | 呈现语义、受控配置、交互和 JSON 信封在 bootstrap。 | 它们组合多层能力，不应制造反向依赖。 |
| D73 | manager 命令按一个脚本加动作参数实现。 | 既保留非交互 CLI，又避免一个动作一个脚本的膨胀。 |
| D72 | 测试不能要求产品路径可由环境覆盖。 | 以一次性容器测试真实路径，不能为方便测试扩大 root 配置攻击面。 |
| D74 | `run_out`、`query`、SQL 查询都通过变量返回输出。 | stdout 会污染调用者或丢失运行状态。 |
| D79 | 菜单常驻，但每轮结束 `exec` 自己重载。 | 命令跑在独立子进程；菜单靠 exec 自身取得新 lib 与新注册表。文件替换一律换 inode，常驻进程读不到变化的字节，K13 因此不适用于菜单。 |
| D86 | 补全动态查询注册表。 | 静态候选表会落后于已安装脚本。 |
| D91 | 组合数组或参数前显式设定空格 IFS。 | 全局换行 IFS 会把审计和错误报告拆成误导性多行。 |
| D92 | bootstrap 最早安装信号兜底 trap。 | 装配窗口收到信号也必须一致返回 131。 |
| D93 | 管理 PHP 配置依据真实 probe，不依据 state 依赖。 | 手工安装的 PHP 不在本工具 state 中，但仍可安全管理。 |
| D94 | 模板渲染后残留占位符即拒绝写入。 | 半渲染配置会以难以定位的方式导致服务失败。 |
| D138 | 不带实例的 `@requires` 在 state 缺失时可回退到 probe。 | state 只表示本工具安装过的内容；带实例约束不得回退为不精确探测。 |
| D237 | 回滚栈由动作显式提交（`os::commit`），而不是让 `os::action_menu` 把每个动作 fork 进子进程。 | 回滚栈是进程级的，而这个二级菜单在同一个进程里连着跑多个动作 —— 前一个动作成功注册的撤销项会一直躺到后一个动作失败，被当成本次的一部分回放掉：现场是「配好 DNS 令牌 → 换配置失败 → 令牌、环境文件、drop-in 全被删掉」，屏幕上只说「应用新配置失败」，用户重输一遍令牌又被同样删掉一次。fork 子进程能天然隔离，但动作里的 state 写入与 probe 缓存都留在子进程里，回到菜单的总览显示的仍是旧数据 —— 而这个菜单存在的理由正是「做完一件事立刻看到结果」。所以隔离靠提交点而不是进程边界。**只作废「必须回滚」类与已备份清单**：撤销是动作，多做一次是破坏；变更清单是告知，中断时用户要知道的是这个进程里发生过的全部事情。已备份清单必须一起清，否则第二个动作改同一个文件时无备份可还原。 |
| D205 | 「默认清单 + 用户增删」统一走 `os::multiselect`。 | 裸名字与 `+/-` 混用、命令行里出现序号、序号既挑又排一律以退出码 2 拒绝；减不掉的项告警而非静默忽略。序号只在交互内有效，清单可被 conf 覆盖后序号会漂。 |

| D240 | 分发的真实性保证只有「GitHub 账号控制权 + TLS」，**没有独立的发布签名**。这是**已识别、已评估、已接受的残余风险**，不是未发现的缺陷。 | manifest 的 SHA256 与被它校验的文件来自同一个仓库、同一条 TLS 连接——能投毒文件的人同样能投毒清单，所以它提供的是完整性不是真实性（§11 §13 已逐字写明，且禁止在文档或输出里说成「已验证来源」）。**记在这里是为了让它不能被静默关闭**：审计问「装到用户机器上的字节凭什么相信」，答案目前就是这一条，而不是「有校验所以安全」。升级路径是可分阶段的：安装器内置公钥先保护此后的 manifest 与自动更新（这部分不依赖首次 `curl \| bash` 可验证），首次安装的真实性另经发行版包、公布安装器哈希或独立渠道发公钥补强；不必等到完整 TUF 才有价值。同类残余风险还有：WordPress 只有官方 SHA-1（防损坏不防定向篡改）、Node 的包与校验清单同源、Caddy 按需构建只有 TLS 与功能验证、Docker/Caddy 的 APT 密钥首次获取是 TOFU。 |
| D241 | 只读面板默认监听所有网卡并用 Basic Auth 挡，**凭据在链路上是明文**。同样是已接受的残余风险，不是实现偏离规范。 | §1 明确设计了「密码」与「来源限制」二选一的门，并把 HTTPS/反代交给 `oneserver caddy`，实现与规范一致。但安全事实不因此改变：Basic Auth over HTTP 的口令可被观察与重放，页面里的主机、服务、端口与日志同样明文。**若威胁模型包含不可信局域网、公网或链路攻击者，这个默认就是错的**，届时要同时改 §1 与实现——建议方向是默认回环、非回环需显式选择且要求 TLS 终止或来源限制（这也更贴合 §15「降低安全性的选项默认为否」，现在的默认恰恰是更宽松的那个）。在改变之前，任何人不得把它表述为「面板已受保护」。 |

## 分发、安装与系统资源

| 编号 | 结论 | 原因与后续约束 |
|---|---|---|
| D97 | 校验失败不能降级到未校验来源。 | 区分不可达与校验失败；后者必须硬失败。 |
| D98 | 校验文件同时兼容裸哈希与带文件名格式。 | 不依赖 `sha256sum -c` 的单一格式。 |
| D99 | 包管理接口放在 bootstrap。 | 它同时依赖 probe、执行、临界区和变更记录；不新建违规层。 |
| D101 | 旧脚本不构成新代码规格。 | 先回答装、配、查、升、卸；个人偏好可覆盖，机器事实先 probe。 |
| D103 | 资源清单只登记组件私有包。 | 通用依赖不能因卸载一个组件被 purge。 |
| D106 | Caddy 插件清单可由受控默认配置覆盖。 | 保证用户可组合插件，同时保持来源和校验边界明确。 |
| D107 | 插件参数支持保留、增、减、替换和 `none`。 | 零输入应可采用默认清单；比较前按确定顺序处理。 |
| D108 | 插件组合排序去重后比较。 | 同集合的不同输入顺序不得破坏幂等。 |
| D110 | Redis 使用发行版源，版本升级交给 apt。 | 不引入未经评估的第三方源和额外生命周期。 |
| D118 | state 与 secure 在 dry-run 下不得写入。 | 预演写入会破坏随后幂等与凭据一致性。 |
| D121 | OneServer 自身以 root 的 unix socket 连接 MariaDB。 | 不把用户 root 密码当作内部依赖。 |
| D125 | state 记录系统事实，而非本次意图。 | 诊断和卸载必须基于当前真实状态。 |
| D126 | 实际安装包本身就是一次变更。 | 用户可见结果不能只统计配置文件变化。 |
| D135 | 脚本辅助函数也以变量返回值。 | `printf` 加命令替换会把提示文字混入数据。 |
| D140 | 删库和恢复前先备份，备份失败即停止。 | 不可逆操作需要可用副本，而非仅一次确认。 |
| D149 | Caddy 管理使用动作式 CLI，不保留常驻二级菜单。 | 与一次性菜单、可脚本化命令和安全 trap 模型一致。 |
| D179 | manifest 从仓库内容生成且不入库。 | 手写清单是第二事实源；含 commit 的发布清单应作为产物。 |
| D184 | 卸载只按资源清单逆序执行。 | 禁止按组件名分支、猜测或自动删除用户数据。 |
| D236 | 归档格式是 `tar.gz` 加一份同名 `.sha256`，不引入 restic / borg；rclone 只负责把做好的归档搬到远端。**代价是无去重、无增量**，认这个代价。 | 备份的价值只在「这台机器没了」那一刻兑现，而那一刻手里可能只有一个对象存储的桶和一台陌生的 Linux：`tar.gz` + `sha256` 用 coreutils 就能验、就能解，**连 oneserver 都不用装**；restic 要二进制、仓库密码、仓库结构三样齐全。对「个人 / 小型 VPS」这个目标用户，恢复路径的依赖数量比省 70% 带宽值钱。**这条理由有两处别当成绝对**：一、加密走 rclone crypt，而 crypt 同样要 rclone 加正确的密码才解得开 —— 「只用 coreutils 就能开」只对**本地那份**成立，而机器没了的场景里本地那份恰恰也没了；二、restic 的依赖常被说重，它是单个静态二进制、仓库格式向后兼容，真正致命的只有密码，而 crypt 的密码一样致命。**「以后在目的地那一层加个 restic 实现、不动归档格式」这条后路走不通**：restic 靠内容分块去重，而每天产出的是一个全新的 gzip 流 —— 源数据改一个字节，压缩流从那里往后全变，分块几乎重合不了，结果是照样传 5 GB，还白背一个仓库依赖。要让它真省，必须让它吃**未压缩**的数据（`tar` 不加 `z`；restic 0.14 起自带压缩），而那就是在动归档布局与 manifest —— §14 把它们列为对外承诺，用户远端上躺着的老归档必须继续恢复得了。所以真正的岔路口不是 rclone 还是 restic，而是**「快照式全量归档」还是「同步式增量」**：restic 是后者的一种实现，`rclone sync` 源目录是更轻的另一种，两者都要放弃「一个文件就是一个完整时间点快照」。**重估判据**：站点总量超过约 10 GB，或上行带宽吃不下每天一次全量 —— 到那时它不再是「代价」而是「这功能没法用」，而重新设计要动的是归档模型，不是传输工具。 |
| D238 | rclone 装官方最新版的 `.deb`（下载后校验 SHA256 再交给 apt），不用发行版源，与 D110 相反；`oneserver backup remote` 每次都与官方最新版对齐。 | 发行版源里那份停在一两年前，而配远端的常规做法是「在自己电脑上跑 `rclone config` 完成 OAuth 授权，再把 `rclone.conf` 拷到服务器」—— 两端版本差得远时，服务器上那份认不出配置里的后端或选项，现场表现是备份跑到上传那一步失败，屏幕上只有一句 rclone 的报错，没人会联想到版本。官方**不提供 apt 源**，只发 `.deb` 与同目录的 `SHA256SUMS`（PGP clearsign，所以 `sha256sum -c` 会整份判失败，必须只取自己那一行来比），正好是规范给第三方软件留的「校验 SHA256」那条路，不必碰官方的 `curl \| bash` 安装脚本。包名仍是 `rclone`，dpkg 把发行版那份当升级覆盖掉，不需要 divert。**取不到官方版时不回落发行版源**：回落等于装上一个已知会失败的版本，然后在几天后那次没人看着的定时备份里再失败一次 —— 已有 rclone 就沿用并说清，一个都没有就当场失败。定时备份（`action_run`）不做这件事：无人值守时不该自己换掉一个正在工作的二进制。 |

## 容器引擎：Podman 与 Docker

| 编号 | 结论 | 原因与后续约束 |
|---|---|---|
| D191 | 不安装 podlet 或 jq。 | 本工具直接生成所需 Quadlet，避免可选转换器和额外依赖。 |
| D194 | 不存在的宿主绑定路径直接拒绝。 | 自动创建空 root 目录会把拼写错误伪装成成功。 |
| D196 | Compose 项目用自有 systemd wrapper 托管。 | 重启后可恢复，并可作为受控 `own:` 资源登记。 |
| D197 | wrapper 的 `ExecStop` 使用 `stop`，不用 `down`。 | systemd restart 不得删除容器、网络或匿名卷；显式 down 才可删除。 |
| D198 | Compose 项目目录原地使用，不复制。 | `.env`、引用文件、相对挂载和 build 上下文必须保留原语义。 |
| D199 | Compose 项目名禁止 `.`。 | 防止 unit 名规范化后与下划线名称冲突。 |
| D201 | Compose 幂等比较渲染后的 `compose config`。 | 仅比较 compose 文件会漏 `.env` 等依赖，哈希全目录又会包含运行数据。 |
| D202 | 卸载 compose 只停止；删除容器/网络须显式 `compose rm`。 | 通用卸载器不能为组件添加分支或隐式执行 down。 |
| D203 | 添加时选择并固定 Compose provider。 | provider 的兼容性不同，unit 必须复用已验证 provider。 |
| D204 | 已托管项目不自动切换 provider。 | 不同 provider 的标签与网络语义不兼容；只有无容器时可重新选择。 |
| D239 | Docker 走官方源 docker-ce，与 podman 的发行版源（D110）相反。 | 发行版的 `docker.io` 落后一到两个大版本，而 `docker compose` 与 buildx 由 Docker 以插件形式发布，跟官方源才配套。代价是一条第三方源与一份密钥，两者都登记进资源清单。 |
| D206 | 公网定位对 Docker 落在 `daemon.json` 的 `"ip"`，不落在防火墙。 | dockerd 把自己的跳转插在 FORWARD 链最前面，ufw 的 `DEFAULT_FORWARD_POLICY` 与放行规则对已发布端口一律不生效；靠防火墙保护 Docker 得到的是「看起来两边都对、实际毫无防护」。绑定地址只对新建容器生效，已有容器只能列出由人重建。 |

## 已核销问题留下的规则

这些 `K` 编号不再是待办，而是仍会造成安全、数据或可用性事故的反例。

| 编号 | 失败模式 | 后续约束 |
|---|---|---|
| K1 | 凭据文件写入或删除破坏了无关条目。 | secure 只经专用原子接口修改，按命名空间清理。 |
| K2 | 不安全的网络监听默认开启。 | 降低安全性默认 `n`，同步实施补偿控制。 |
| K3 | 数据库账号默认通配来源和过宽授权。 | 默认最小权限与本地来源；扩大范围需显式选择。 |
| K4 | `eval` 与拼接命令导致凭据泄露或 root RCE。 | 禁止 eval，命令以数组和受控接口执行。 |
| K5 | `/tmp` 锁可被符号链接攻击。 | 锁和敏感临时文件仅位于受控 `/run` 目录。 |
| K6 | 管理定时任务误清空用户既有任务。 | 只管理自己登记的资源，不能覆盖未知用户资产。 |
| K7 | 多实例覆盖另一实例的凭据或 state。 | 使用完整实例标识和命名空间。 |
| K8 | 失败信息被重定向，终端静默。 | warn/error/失败报告走 stderr，日志不替代用户可见错误。 |
| K9 | SQL 字符串拼接。 | 只使用 SQL 转义接口和安全默认连接方式。 |
| K10 | root 管道执行第三方远程脚本。 | 下载先校验，再处理；不执行未经验证远程内容。 |
| K11 | 安装器以旧标记短路，不能修复重装。 | 安装器以 manifest 与目标状态校正，不以历史标记跳过。 |
| K12 | source 配置或凭据文件。 | 严格解析允许的键值，不把数据当代码执行。 |
| K13 | 覆盖正在执行的脚本。 | 派发和更新用 exec，切换器原子替换并支持回滚。 |
| K14 | 探测无超时导致界面卡死。 | 所有 probe/query 有超时和显式降级状态。 |
| K15 | 运行时从网络取模板。 | 模板随分发落地，只读取本地受控目录。 |
| K16 | 前置权限检查发生得太晚或信息不清。 | bootstrap 在副作用前统一校验权限并用专属退出码。 |
| K17 | 模板指向不存在的日志路径。 | 写入模板前验证相关目录/服务语义，测试覆盖实际落地。 |
| K18 | 回滚栈跨动作累积，一次失败撤销了上一个动作已经做成的事。 | 回滚栈作用域是进程；同进程连做多个动作时，每个动作成功即 `os::commit` 作废其撤销项（D237）。 |
| K19 | 只读通道丢弃 stderr，命令把失败原因写在那里，用户与日志都拿不到。 | 取值默认丢 stderr，但把结论写在 stderr 的命令必须显式 `--want-stderr`；失败报告里不许出现空的原因行（K8 同源）。 |
