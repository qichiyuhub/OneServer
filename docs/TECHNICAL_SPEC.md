# OneServer 技术规范

本文件定义**设计方向与骨架**：边界、分层、模型、语义。它的作用是让改动不偏离，不是罗列细节。

- **接口签名与参数**见 `docs/API.md`（由 `make api` 从 `lib/` 生成，需要时检索，不必通读）。
- **决策理由与踩坑记录**见 `docs/DECISIONS.md`。
- 本文件与实现冲突时，先判断是文档过期还是实现缺陷，**不得无声降低安全要求**。框架有缺口时先改本文件（需同意），再改代码——不在代码里绕过。

标 `[CI]` 的条款能被 `tests/lint.sh` 自动发现，其余靠人工 review。**没有标记不等于可以违反**，标记只说明机器能不能替你发现。（`lint.sh` 共 21 项检查，其中 shellcheck、shfmt、`disable` 审计与接口测试覆盖不对应本文件的具体条款。）

适用范围：

- `script/**` —— 受全部条款约束。其中不带 `@command` 的是**内部步骤脚本**（由 systemd 或框架直接执行），不适用元数据与路由条款，文件头、`@privilege` 与领域边界照旧（§5）。
- `bin/**` —— 前端，不适用元数据与前置检查，其余照旧。
- 根 `uninstall.sh` —— 它 `source` 得到 `lib/`，因此**不是**自包含例外：文件头、路径单一来源、领域边界一律照旧。放在仓库根只是为了不进注册表（卸掉整个工具不该躺在日常操作列表里）。
- `lib/**` —— 不适用面向脚本的接口条款（元数据、参数、语义输出、`desc` 固定字符串），但 §4.3 分层与全部安全禁令（凭据、`eval`、未经校验的远程内容、原子替换）同样约束它。
- `install.sh` 与更新切换器 —— **两个自包含例外**：前者跑在还没有 `/opt/oneserver` 的机器上，后者要替换的正是自己脚下那棵树，两者都 source 不了 `lib/`，因此自带输出与参数解析。安全禁令与校验要求照旧，框架接口条款不适用。**它们不是可以照抄的样板**，`script/**` 下这么写就是违约。

## 1 · 产品边界

面向 Debian 与 Ubuntu 的 Bash 服务器管理工具，装在 `/opt/oneserver`，以 root 执行需要修改系统的命令。其他发行版必须在产生系统副作用前以 4 拒绝。提供 CLI、一次性菜单与按脚本发现的功能命令。

Podman 是组件级例外：本项目以 Quadlet 托管容器，要求 Podman ≥ 4.4。机器尚未安装 Podman 时，发行版源安装路径只接受 Debian ≥ 13 / Ubuntu ≥ 24.04；较旧系统明确拒绝并引导使用走 Docker 官方源的 `oneserver install docker`。机器已有 Podman 时按实际版本判断，不因发行版版本误拒绝。

**不做**：RHEL / Alpine、运行时依赖、Python/Go 重写、操作型 Web 面板、可插拔渲染器、路径配置文件、注册表缓存、分域锁、JSON 内部存储、运行时插件框架、单进程 source、i18n、主题热切换。改变这些边界须先取得明确决定。

「不做操作型 Web 面板」的**补集是允许的**：`oneserver web` 提供一个**只读**面板——定时把 probe 与 state 采成数据文件，页面只显示、不改任何东西，连刷新按钮也只是重新拉取已落盘的数据而不触发服务端探测。它没有服务端逻辑（静态文件 + 浏览器）。**必须有一道访问门槛**——只读跟要不要门是两件独立的事，不能因为面板不做操作就顺带也不设门。门有两种形态，enable 时二选一，不存在"都没有"：默认监听所有网卡、用 basic_auth 挡；选择不设密码时，必须在同一步把来源限制落实到配置里（监听收窄到回环，或只对指定网段应答）。**一旦页面上出现任何能改变服务器状态的操作，它就越过了这条边界。**

不把旧版本脚本当作需求。新功能须基于完整的安装、配置、探测、升级、卸载生命周期设计；个人偏好必须可覆盖，任何机器假设必须先经 probe 确认。

## 2 · 运行链路

一条命令从敲下到结束经过的环节。**知道自己的代码落在哪一段，比逐条背规则更能避免违规。**

`oneserver install php --version=8.3`：

1. `bin/oneserver` 设 `OS_BOOT_MODE=frontend`，先 source `bootstrap.sh` 再 source `registry.sh`——顺序是硬的，`registry` 要用 `bootstrap` 定义的接口。
2. bootstrap 前端模式只做装配、日志与 trap，**argv 原样保留**。
3. `registry::scan` 扫 `script/**` 每个文件头 40 行的元数据。**每次都扫，不缓存。**
4. `registry::resolve` 按命令词最长匹配定位脚本；匹配不上报未知命令、给近似建议、退 2。
5. 校验脚本执行位（缺了的表现是"这条命令莫名其妙不存在"），`shift` 掉已匹配的命令词，`exec` 目标脚本——**前端进程到此被替换，不留父进程**。
6. 目标脚本自己 source `bootstrap.sh`，这次是命令模式，走 §5 的固定前置顺序直到取锁。
7. 脚本 `main()`：`probe::` 判是否已是目标状态（幂等）→ 交互收参数 → 执行封装落副作用 → 写 state 与资源清单 → 语义输出。
8. 退出时 EXIT trap 落 probe 快照、释放锁；失败时打印变更清单。

**菜单**同样加载注册表，按 `@requires` 过滤掉不可用条目、按 `@command` 折叠出层级、按 `@order` 排序渲染，选中后 fork 子进程执行，命令结束后 `exec` 自己回到列表；菜单进程不持锁，锁归被派发的命令。**补全**查同一份注册表，没有第二份命令清单。**卸载**反向走：读 state 的资源清单逆序执行，不重新探测系统。

一句话概括：**元数据是命令的唯一真相源，CLI、菜单、补全三个消费者都从它派生；副作用只发生在被派发的那个脚本进程里。**

## 3 · 不变量

这些是判断一次改动"是否偏离"的标尺。违反其中任何一条，改的就不再是这个项目。

1. **前端不改变主机状态** —— `bin/**` 只做路由、渲染与只读探测。**[CI]** 唯一的例外是框架私有、按 PID 隔离的 `/run` 记号（菜单靠它知道刚才是不是选了「返回上一层」）：那是一次派发的进程间信号，不是主机上的任何东西。**不得由此推广成前端可以随手 `rm`/`mv`/`cp`** —— 判据是「这个文件除了框架自己还有谁读」，答案不是「没有」就不在例外里。
2. **单一装配点** —— 所有模块只由 `bootstrap.sh` 装配，`lib/` 之间不互相 `source`。**[CI]**
3. **单一全局锁** —— 会改变系统状态的 root 命令自动持锁，锁在 `/run`，不分域、不自建。两个例外都只给周期性命令（§6）：`root-nolock` 零系统副作用，压根不需要锁——否则一个每十秒采一次的定时器会随机挡住用户敲的真实命令；`root-trylock` 有副作用但晚一轮无所谓，试一次拿不到就以 0 退出，**不把「用户正占着锁」记成失败**。
4. **凭据只经 `lib/secure.sh`** —— 不进 argv、日志、state、公开数据与备份明文；脱敏在写入前发生。
5. **dry-run 零变更** —— 包括不建目录、不写 state、不写审计。
6. **幂等** —— 第二次执行退出码 0 且不产生任何新变更，包括不重启服务。
7. **副作用可追溯** —— 每个副作用都经框架接口，都归入 §10 三类之一；失败与中断时框架列出已发生的变更。
8. **卸载只读资源清单** —— 不探测、不猜测、不按组件名写分支。
9. **命令永远跑在自己的进程里** —— 前端不在本进程内执行命令逻辑；菜单在命令结束后 `exec` 自身重载，绝不带着旧 lib 与旧注册表继续服务。
10. **脚本层只调 `os::` 与 `probe::`** —— 框架内部前缀与 `_` 私有函数一律禁止；前端另见 §4.3。**[CI]**
11. **系统事实只出自 `probe::`** —— 脚本不自行探测。
12. **降低安全性的选项默认为否** —— 且放宽时必须同步落实补偿控制。

## 4 · 结构

### 4.1 仓库目录

| 目录 | 职责 |
|---|---|
| `bin/` | 无副作用的 CLI 与菜单入口 |
| `lib/` | 常量、输出、基础设施、领域能力、装配 |
| `script/install/` `manage/` `ops/` | 安装部署 · 服务与容器管理 · 备份诊断更新卸载 |
| `templates/` | 本地配置模板、菜单分组、新脚本骨架 |
| `packaging/` | 更新切换器、systemd 单元、补全、logrotate、清单与接口生成器 |
| `tests/` | lint、bats、容器测试环境 |
| `docs/` | 规范、接口参考、决策记录；不进分发物 |
| `install.sh` · `VERSION` | 引导安装器 · 分发版本输入（不得以提交状态代替） |

### 4.2 运行时文件系统

路径的单一来源是 `lib/paths.sh`。脚本**禁止**硬编码路径 **[CI]**，**禁止**引入路径配置文件。（判据是赋值右值与 `for … in` 列表里的路径字面量；命令参数位置上的路径多是给人看的文本，而 `desc` 本就被强制成固定字符串。）

| 路径 | 用途与约束 |
|---|---|
| `/opt/oneserver` | 程序目录，更新时整体原子切换 |
| `…/state/components.tsv` | 组件清单，0640，`.bak` 是上一版 |
| `…/data/` | 工具自己的持久运行数据（面板历史曲线、告警去重基线），`root:root`、0750。**与 `state/` 分开**：那是组件清单，卸载按它反向执行，混进与组件无关的文件是拿卸载语义冒险。这里的东西丢了只是可惜，不影响正确性。由 `install.sh` 与切换器保证存在——面板的 unit 用 `ReadWritePaths` 精确列了它 |
| `…/tmp/` | `os::tmpdir` 的**唯一**落点（D244）：下载的压缩包、解包暂存、要现场执行的二进制。放在程序目录下而不是 `/var/tmp`——后者 1777，本地用户能抢先建出目录名，而属主校验会因此拒绝使用它，等于让整个工具停摆。切换器不碰它，卸载随 `OS_ROOT` 一起收走 |
| `…/secure.conf` | 凭据，0600 |
| `/etc/oneserver/*.conf` | 可选覆盖，属主 root、权限受限、严格 `key=value`、**禁止 source** |
| `/var/log/oneserver/` | 人读日志 · 机读 JSONL · 审计，0750 |
| `/var/backups/oneserver/archives/` | 布局 `<type>/<name>/<时间戳>.tar.gz`，**改它等于已有归档恢复不了** |
| `/run/oneserver/` | 全局锁与运行时标记；tmpfs，重启即空 |
| `/run/oneserver-public/` | 唯一放宽到 0755 的目录，存 probe 快照与只读面板的数据（含日志副本）。**tmpfs，重启即空**：这里每一项都是「此刻的快照」，重启之后上一秒的内存占用与容器状态全部作废，采集器几秒内重建——把它们写到盘上，是为一个没人需要的属性付磁盘寿命。因此这里**只放快照**：需要跨重启存活的东西（去重状态、计数、用户要留的记录）一律不属于这里，放进来就是把重启当成了数据丢失。**永不含凭据**；放进来等于对本机所有用户公开，因此**审计日志永不进这里**。**这个放宽是有代价的，要认**：组件清单、防火墙规则表、监听端口与操作日志尾部对本机任何非特权用户可读，合起来是一份现成的侦察材料。接受它的前提是「这台机器上没有不可信的本地用户」——若这条前提不成立，收紧到专用组，而不是继续往里放东西 |

`/run` 下的目录重启即空，**禁止**靠进程自己 `mkdir` 来保证它存在：unit 挂命名空间（`ReadWritePaths=` 等）发生在 `ExecStart` **之前**，路径不存在就是 `226/NAMESPACE`，进程根本没起来。这类目录一律由 `RuntimeDirectory=` 建；oneshot 单元还必须配 `RuntimeDirectoryPreserve=yes`，否则每轮退出就把它删了。

### 4.3 lib 分层

只允许向下依赖；**禁止**同层依赖与模块间 `source` **[CI]**。

| 层 | 模块 | 约束 |
|---|---|---|
| L0 | `paths` `defaults` `theme` | **只有变量赋值**，不得有函数、条件、命令调用 **[CI]** |
| L1 | `ui` `log` | 只依赖 L0，彼此不依赖 |
| L2 | `exec` `errors` `lock` | 只依赖 L0–L1 |
| L3 | `secure` `state` `sql` `systemd` `firewall` `probe` `template` | 只依赖 L0–L2 |
| L4 | `bootstrap` `registry` | 可依赖全部；`registry` 由前端在 bootstrap 之后 source |

`probe` 是 L3 中唯一允许被脚本层直接调用的模块，其余经 `os::*` 暴露。`lib/**` **禁止**依赖 `jq`、`python`、`perl` **[CI]** 或任何非 coreutils/util-linux 命令。

**前端的白名单更宽**：`bin/**` 是框架的一部分而非消费者——它 source `bootstrap` 与 `registry`、实现路由本身，因此额外允许 `registry::` 与 `log::`。记录"这条命令派发到了哪个文件"是框架事件，语义输出层只管给用户看的消息，从设计上不覆盖它。

新增共享函数前先验证已有接口不能表达；两处相似不提取，第三处再评估。

## 5 · 进程模型

分发物分三类，各自的规矩不同：

| 类别 | 是什么 | 执行位 | 文件头四件套 |
|---|---|---|---|
| 前端 | `bin/**` | 100755 | 适用 |
| 公开命令脚本 | `script/**` 中带 `@command` 的 | 100755 | 适用 |
| 内部步骤脚本 | `script/**` 中不带 `@command` 的，由 systemd 或框架直接执行 | 100755 | 适用 |
| 其余分发物 | `lib/**` `templates/**` `packaging/**` | 100644 | 不适用 |

内部步骤脚本**不进注册表、不进菜单、不进补全**（那三者都以 `@command` 为准），因此不需要菜单与路由字段；但它同样以 root 跑、同样由 bootstrap 读取 `@privilege` 与 `@requires_lib`，其余约束全部适用 **[CI]**。把它写进 `script/**` 而不是 `packaging/**`，正是为了让这些检查覆盖到它。

命令脚本与内部步骤脚本都以严格 Bash 设置、受限 `PATH`、`umask 027` 开头，随后 `source bootstrap.sh`，全文件仅一次 **[CI]**。根卸载器同此。执行位以 git 索引为准 **[CI]**——清单的权限取自索引，多余的执行位会一路带到用户机器上，缺失的执行位则让 systemd 以 `203/EXEC` 起不来。**判据是「谁会去执行它」，不是「它有没有 `@command`」**：采集器与通知器没有 `@command`，却是 unit 里 `ExecStart=` 指着的那个文件。

更新切换器是「其余分发物」里唯一可执行的一个（`oneserver update` 要求它 `-x`），lint 靠文件内的 `# os-contract: updater` 标记认它、不认路径。它与 `install.sh` 一样不 `source` `lib/`，因此文件头那条对它们不适用（见开头的适用范围）。

前端设 `OS_BOOT_MODE=frontend`，跳过元数据、全局参数、EUID、`@requires` 与取锁五步——它们只对命令有意义；装配、日志与 trap 照常。**argv 原样交还**：`--version=8.3` 是目标脚本的参数，前端吃掉它就再也传不下去。该变量若从环境继承，bootstrap 以退出码 4 拒绝：否则任何人都能让一条真命令跳过取锁与 EUID 校验。

**前置检查顺序固定**：解析元数据 → 解析全局参数 → 校验 EUID → **初始化日志与 trap** → 校验发行版 → 校验 lib API → 校验 `@requires` → 取锁（`@privilege root` 等到手，`root-trylock` 试一次就走）。日志与 trap 排在多数校验之前是有意的——此后每一步的失败都该被记下来。

派发出去的命令**必须是独立进程**：CLI 直接 `exec` 目标脚本；菜单 fork 一个子进程跑它，等它结束后 `exec` 自己回到列表。

菜单之所以敢常驻，是因为本项目的文件替换一律「同目录临时文件 + `mv` 换 inode」（§11）——正在运行的进程握着旧 inode，脚下的字节不会变；`>` 就地截断那种写法全项目禁止。而「更新完菜单还是旧的」这个真实风险，由**每轮结束都 `exec` 自己**解决：重新装配 lib、重新扫注册表。

菜单进程不持锁，锁由它派发出去的命令持有。

## 6 · 命令发现与元数据

注册表扫描 `script/**` 头部 40 行内的元数据，CLI、菜单与补全全部由它派生。**新增命令只需添加一个带完整元数据的可执行脚本，不改任何前端**；补全必须动态查询，不得维护静态快照。

字段：`@command`（全局唯一，路由取最长匹配）· `@name` · `@self_name`（可选，仅**有下级的命令**需要：它在自己那一屏的第一项显示什么，不填则沿用 `@name`。两处语义不同——上一层答「这个功能叫什么」，自己这一屏答「选中它会执行什么」，共用一个名字的结果是标题与第一项逐字重复）· `@group`（取值须存在于 `templates/groups.conf`）· `@order`（**组内**唯一，只决定同组内的先后；菜单编号按屏重排 1..N，不上屏；建议步长 10，往中间插一个脚本时取中间值，不必推动其余各条）· `@privilege` · `@requires` · `@requires_lib` · `@provides` · `@provides_unit` · `@args` · `@description`。静态可判定的部分——组内编号与命令名撞车、`@group` 取值不存在、`@requires_lib` 高于 `lib/API_VERSION`、`@provides_unit` 缺前缀——在提交时就查 **[CI]**；`doctor --selftest` 查的是装到机器上的那一份，两边消费者不同，都不能省。

取值语法：`@requires` 为 `<type>[:<instance>][<op><version>]`，`<op>` 取 `>=` `>` `=`，多项逗号分隔；`@requires_lib` 为 `>= X.Y`；`@provides` 声明的是**形态**，`<...>` 是运行期才确定的实例占位符；`@args` 中 `<...>` 表示必须带值，`[...]` 表示可选开关。

`@requires` 不满足时**菜单隐藏该条目，CLI 以退出码 3 终止并指明缺哪个**。两个前端处理不同是有意的：菜单是浏览，列出用不了的东西只是噪音；CLI 是明确指令，必须说清为什么没执行。

**菜单层级取自 `@command` 本身**：多词命令的父命令若也已注册且可见，该条目折叠到父条目下，选中父条目才展开（`podman image` 折进 `podman`）；父命令未注册或被 `@requires` 隐藏时留在顶层，否则条目会藏在一个选不中的东西下面。**禁止**为层级另设元数据字段——命令路径里已经写明谁是谁的下级，第二份声明迟早与它对不上。折叠只改显示在哪一层；跨层直达靠输入命令名（最长前缀路由），不靠编号。

`@group` 挂 `parent`（`templates/groups.conf`）时该分组在父分组里收成一条虚拟项，展开显示该分组下**未被命令折叠**的成员（即 `parent<0` 的那些——已经折进别的命令下的不重复出现）。**虚拟项展开后只剩一个成员时自动跳进那个成员，不再多问一次**：唯一能选的东西不构成选择。这条只影响是否弹出这层列表，折叠规则与 `@order` 排序不受影响。分组可以再挂分组，展开层同时列出成员与子分组；**嵌套深度有上限**，`parent` 成环时按上限截断而不是无限递归。

分组在上一层的说明列**列出它的成员与子分组名**，回答「现在能点什么」。只剩一个可见成员时改取 `templates/groups.conf` 的可选说明列，回答「这一栏覆盖什么」：那时列成员名等于把分组名重说一遍，而顶上那条成员脚本的 `@description` 说的是一条命令干什么——「只剩一个」通常只是别的成员被 `@requires` 隐掉了。分组没写说明时仍回落到成员的 `@description`；顶层分组只作为分区标题出现，标题没有说明列，**给它写说明是无效数据** **[CI]**。

`@privilege root` 校验 EUID 并取锁；`root-trylock` 校验 EUID 并**试一次锁，拿不到就以 0 静默退出**；`root-nolock` 校验 EUID 但**不取锁**；`any` 不校验不取锁。

`root-trylock` 给的是**有副作用、但这一轮做不做都行**的周期性命令（例：把新告警发出去）。它与 `root-nolock` 的分界很清楚：后者零副作用，所以根本不需要锁；前者确实要改东西，只是**晚一轮无所谓**。

取不到锁时以 0 退出而不是 5，因为**锁被占是预期内的正常情形，不是故障**：用户在菜单里停留期间，被派发的那条命令一直持锁。把它记成失败的后果实测过——每一轮往 JSONL 写数条错误，而日志本身是面板要发布的产物，于是「用户正在使用工具」被放大成持续的整份重写与满屏红字。**试锁的等待必须是秒级**：等满默认的 30 秒再放弃，与直接失败没有区别，只是把一轮的间隔整个吃掉。

此处的静态门禁覆盖公开写接口、常见外部写命令与指向 `OS_*`/持久绝对路径的
输出重定向；动态构造或间接执行无法由文本检查完备证明，仍须代码审查。
`root-nolock` 只允许用于**零系统副作用**的命令：可以读任何东西，可以经 `os::write_public` 发布 `public/` 下的只读产物，**禁止** `os::run` 与 `os::run_out`、写组件清单、写凭据、写配置、落模板、启停服务、调包管理、`os::tmpdir`，**也禁止往任何持久路径写文件**（只允许 `os::query` 的只读查询、`probe::` 与只读 state getter）**[CI]**。`os::tmpdir` 是后加进这张表的：它从前落 `/run` 的 tmpfs 不算持久写，落点搬到磁盘之后（D244）调它就是在盘上建目录。给它 root 而不给锁是安全的，因为它不改任何被锁保护的东西；不给它 `any` 是因为非 root 探测只会得到降级值，把降级值写进快照比不写更糟。

「不往持久路径写」这条要单独说，因为它被绕过过：采集器曾用 `os::install_file` 把面板历史刷到盘上，理由充分（那条曲线要跨重启），但**一个不持锁的进程在写持久文件**正是这一档要防的事。**需要持久化的遥测一律拆成 `root-trylock` 步骤**——有副作用、晚一轮无所谓，正好是那一档的定义。`public/` 里的历史是**展示副本**，不是真相源；盘上那份才是，它的权限、保留窗口与「丢了会怎样」都必须写清楚（丢了只是曲线断一截，不影响任何判断）。

**不持锁的代价必须说清**：采集可能撞上一次正在进行的变更，快照因此可能捕捉到中途状态（装了一半的包、刚停还没启的服务）。消费者**禁止**把快照当作事务一致的视图，下一轮采集会自行修正。

`@provides_unit` 必须区分来源：`own:` 是本项目提供、卸载时删除文件；`ext:` 由发行版包提供，卸载时**只停止与禁用**——删它是在破坏 dpkg 管理的文件。脚本操作的每个 unit 必须能匹配某条声明。

`@description` 的**显示宽度不得超过 48 格** **[CI]**（按显示宽度算，一个中文字两格）。它同时喂 `--help` 与菜单第二列，而最窄的那一屏留给说明列只剩 49 格：写成一整句的结果是菜单里每条都以 `…` 收尾，说明列的意义当场归零。`groups.conf` 的分组说明落在同一列，同一个阈值 **[CI]**。

元数据是前端发现与校验的输入，不是脚本可自行修改的运行时状态。

## 7 · 组件标识

语法 `<type>[:<instance>]`。**实例是身份，版本是属性**：同一 type 的多个实例在 state 中各自独立，各有独立的 unit 列表与凭据命名空间。

多实例脚本必须使用完整标识，**禁止**以 type 名覆盖 state 或凭据——扁平标识遇到第二个同类事物就会静默损坏。卸载时存在多个实例，**必须**列出全部并要求指明完整标识，禁止猜测或默认全卸。

## 8 · 退出码

| 码 | 含义 | 系统状态 |
|---|---|---|
| 0 | 成功，含"已是目标状态" | 已达目标 |
| 1 | 一般失败 | 已按 §10 处理并打印变更清单 |
| 2 | 参数错误 | 未变更 |
| 3 | 依赖缺失 | 未变更 |
| 4 | 环境不支持（发行版、权限、lib API） | 未变更 |
| 5 | 获取锁失败 | 未变更 |
| 130 | 用户在确认点选择否 | **一定未变更** |
| 131 | 执行中途被信号打断 | **状态未知**，已打印变更清单 |

**禁止**使用未定义的退出码。130 与 131 必须严格区分——调用方靠它决定要不要继续。

**外部命令的退出码禁止穿到进程出口。** 未定义的码由框架归一为 1，但外部命令完全可能撞上表里的码——tar 用 2 表示 fatal error，`systemctl is-active` 用 3 表示服务没在跑——那时框架会按「未变更」处理而**跳过回滚**。因此每个 `os::run` 的失败都必须由脚本显式转成本表里语义正确的码（通常是 `|| os::die 1`）。框架对此有一道兜底：退出码为 2/3/4 而变更清单非空时，该码与「未变更」矛盾，一律归一为 1 并按一般失败处理（回滚 + 变更清单）。**dry-run 下这道兜底不生效**——预演里没有任何命令真的执行，清单表达的是「将会发生什么」，拿它当已变更的证据会把一次正常的预演参数错说成执行失败。

## 9 · 交互、参数与输出

**全局参数**由 bootstrap 统一解析，脚本不自行处理，也不得与之重名：`--help`/`-h` · `--dry-run` · `--non-interactive` · `--yes`/`-y` · `--force-destroy` · `--verbose` · `--no-color` · `--output text|json`。这组参数的语义是对外承诺（§14）。

**交互完备性**：每个交互调用点必须带 `--arg <名字>`，其名字集合与 `@args` **双向相等**。计数相等不算——复用同一个 arg、循环里的 ask、分支里的 ask 都会让计数通过而实际不匹配。缺一个参数的后果是 `--non-interactive` 下静默替用户做出他没同意的选择。

`--non-interactive`：给了就用，未给且有显式默认值就用默认值，否则以 2 终止并指明缺哪个。**凭据没有默认值**，只能手输，非交互下直接失败。

**呈现分层**：脚本用语义接口表达"这是什么"，`lib/ui.sh` 决定"长什么样"，`lib/theme.sh` 是纯数据。`script/**` 与 `bin/**` **禁止**出现 ANSI 序列、排版用边框字符、`printf` 宽度格式符、`OS_THEME_*` 引用、`ui::*` 调用。渲染层必须处理 TTY 判断、`NO_COLOR`、色深降级，且所有对齐按**显示宽度**而非字节数计算。

**分流**：错误与警告走 stderr，进度与成功走 stdout，命令原始输出仅进日志。**禁止**把错误输出放在被重定向的复合块内——用户会看到脚本无声退出。脱敏在**写入前**发生，直接 `cat` 日志也必须安全；调用栈仅进日志。

**机器可读输出**：`--output json` 时呈现层整层静默，stdout 只有一个信封对象：

```
{schema, command, ok, exit_code, ts, data:{…, items:[]}, messages:[{level,text}]}
```

值一律为字符串。`data` 只能由框架接口产生，**禁止**手写 JSON、**禁止**依赖 `jq`。

## 10 · 执行语义

所有外部副作用经执行封装，只读查询经带超时的查询接口，**禁止**裸调外部命令、**禁止 `eval`** **[CI]**（全项目零使用，不留例外；确需时先改本文件说明理由）、**禁止**手写重试循环。`desc` 必须是固定字符串 **[CI]**。

**`sh -c` / `bash -c` 的脚本文本必须是静态的，值一律经位置参数传入** **[CI]**：`sh -c '… "$1" …' sh "${值}"`。把值展开进脚本文本（`sh -c "… '${值}' …"`）是 `eval` 的另一种写法，禁令同等适用——它绕开的只是那条静态检查，不是那条规则。这不是理论问题：恢复流程曾把 `rclone lsf` 返回的**远端目录名**拼进内层 shell，于是「谁能往备份桶里写东西」等于「谁能在恢复机上以 root 执行命令」。**判据是值的来源无关**——「这个值恰好只含安全字符」是会在重构中静默失效的保证，而结构上传不进语法的值不需要这种保证。静态检查只覆盖单行内的 `${` 展开；跨行脚本文本与先拼进变量再传入的写法查不出来，仍须代码审查。

**一次调用留下的东西，必须能被需要它的那个 shell 读到。** 命令替换 fork 子 shell，子 shell 里发生的赋值、清理栈登记、探测缓存写入**全都回不到父进程**——后果不是不方便，是判错，或者更隐蔽：动作看起来成功了，它留下的账却记在一个转瞬即逝的进程里。

由此分成三类：

- **留下需要善后的资源的接口** —— `os::tmpdir`、`os::sql_defaults_file`。它们建出目录后要把路径登记进清理栈，而清理发生在父进程的退出路径上。**一律经显式输出变量交回，任何情况下都不得在命令替换里调用**：`d=$(os::tmpdir)` 会让目录照建、清理列表始终为空，每调用一次泄漏一个，而清理代码看上去一直在跑。
- **执行与探测接口** —— `os::run` `os::run_out` `os::query`、全部 `probe::*`。它们把结果与状态放进单槽全局变量（§下段）。**谁调用谁就地读**：写在命令替换里，只有当那次调用的结果与状态**在同一个子 shell 内被读完**才成立（脚本自己的只读辅助函数常是这种形状），凡是父进程还要拿状态判断的，就必须在父进程里调。
- **纯值接口** —— 字符串转换（`os::sql_ident` `os::sql_str`）、只读 getter 与列表枚举（`os::state_get` `os::state_list` `os::state_units`、`probe::describe`）。它们不在进程里留下任何东西，经 stdout 返回是 shell 的正常用法。

**经显式输出变量交回结果的函数，其局部变量一律带 `__<模块缩写>_` 前缀** **[CI]**（`__os_`、`__cd_`、`__db_`、`__rs_`）。`local` 在 bash 里是动态作用域：局部变量与调用方传进来的那个名字撞上时，`printf -v "${出参}"` 写进去的是函数自己那个副本，函数一返回就没了——**调用方拿到空串，而且没有任何报错**。恢复流程踩过的形态是 `rs_safe_extract` 内部 `local stage`、调用方也写 `local stage` 并把 `stage` 当出参传进去：隔离目录建了、归档解了、审计过了，回到调用方 `${stage}` 仍是空串，于是下一步 `chown -R -- "${stage}/${root}"` 作用到了 `/test` 上。前缀不必全局唯一，只需与调用方可能用的名字不相交——**调用方传的是自己声明的小写变量名，带前缀的撞不上**。同一条约束下，`local IFS=' '` 这类大写的特殊变量不在其列。

新增接口时先回答「这次调用在进程里留下了什么」。答不上来，说明它做的事太多。

框架的结果变量都是**单槽、易失的返回通道**：`os::run` / `os::run_out` / `os::query` 会一起覆写 `OS_RUN_STATUS`、`OS_RUN_OUTPUT`、`OS_RUN_SKIPPED`；`probe::*` 会覆写 `OS_PROBE_STATUS`、`OS_PROBE_VALUE`、`OS_PROBE_SOURCE`；模板放置会覆写 `OS_TEMPLATE_CHANGED`；逐行替换会覆写 `OS_REPLACE_CHANGED`。调用方必须在紧邻调用后立刻读出或复制需要的值，禁止在两者之间插入另一次同类调用。新增接口优先使用显式输出变量，避免继续增加全局单槽。

**判据**：两个以上的地方需要同一个系统事实，它就必须是 `probe::`，不是一次性查询。

**dry-run**：有副作用的不执行并打印将执行的命令，只读的照常执行——只读也跳过的话，预演的是"假装要做什么"而不是"基于真实系统会做什么"。一旦跳过过副作用，真实状态与推演状态即分叉：此后探测结果标注为不可信，遇到依赖未满足**禁止**报错退出，必须声明预演到哪一步并以 0 结束。**会撒谎的 dry-run 比没有更危险。**

**幂等**：已达目标状态的步骤跳过并说明，禁止报错，禁止产生新变更。写文件前先判断内容是否变化。

**副作用三分类**，每个步骤必须归类，**禁止**笼统地全部注册回滚——回滚动作本身也是副作用：

| 类别 | 例 | 处理 |
|---|---|---|
| 必须回滚：本次创建、可安全撤销 | 写配置、建库建用户、加防火墙规则 | 注册回滚，失败时逆序撤销 |
| 禁止自动回滚：可能是用户既有资产 | apt 安装、启停系统服务、改内核参数 | 只记录，失败时打印由人判断 |
| 先备份再改：不可逆或难重建 | 覆盖已有配置 | 先存副本，回滚即还原 |

**回滚栈的作用域是进程，不是动作。** 一个进程里连着跑多个动作（`os::action_menu` 的常驻二级菜单就是），前一个动作成功注册的撤销项会一直躺在栈里，被后一个动作的失败当成自己的一部分回放掉。动作做完即 `os::commit` 作废其撤销项与已备份清单——变更清单不动，那是告知不是动作。

**中断**：捕获 `INT`/`TERM`/`HUP`，**不执行回滚栈**（中断点状态未知，回滚很可能加重破坏），打印已发生的变更清单，以 131 退出。包管理事务、原子替换、state 与凭据写入、更新切换必须置于临界区；中断后再次执行必须安全。

**不可逆操作**必须：先落可恢复副本或明确告知不可恢复 → 打印精确清单（不接受"将删除某站点"这种概括）→ 要求打全名确认 → **`--yes` 对其无效**，必须独立的 `--force-destroy` → 支持 dry-run 预演。`--yes` 若能一路批准删库，无害命令上的习惯迟早被复制到危险命令上。

| 领域 | 唯一入口 | 禁止 |
|---|---|---|
| 凭据 | `lib/secure.sh` | `source` 或直接改写凭据文件；扁平 key；进 argv / 日志 / state / 公开数据 / 备份明文 |
| SQL | `lib/sql.sh` 的转义与执行接口 | 拼接 SQL |
| systemd | `lib/systemd.sh` | 手写 `systemctl`；直接写 unit 目录；删 `ext:` unit 文件；**操作 crontab**（定时一律用 timer） |
| 系统事实 | `lib/probe.sh` | 脚本自行读 os-release、查包、查 unit、查端口、查磁盘、查容器 |
| 防火墙放行 | `lib/firewall.sh` | 自己写规则匹配正则；自行拼 `ufw allow`（两个例外见下） |
| 包管理 | `lib/` 的包接口 | 脚本里直接 `apt-get` **[CI]** |
| 文件写入 | 模板与替换接口 | `>` 就地截断；`sed -i`；`install`/`cp` 覆盖同路径 |

防火墙那一行的两个例外都是**语义不同**，不是豁免：`firewall` 命令自身是这个领域的实现（它还要删规则、按序号定位、处理端口与序号的歧义）；SSH 加固要的是「这一条是不是本次新增的」——它跑完看 ufw 输出判定，而不是事先用 probe 判幂等，因为放行 SSH 端口这一步**不能因为判错而跳过**。判定与执行以外的东西不在 `firewall.sh` 里：问不问、怎么问、拒绝之后说什么属于脚本层（§9 要求每个问句配一个 `--arg`，参数名属于那条命令）。

凭据的命名空间由框架统一生成，脚本**禁止**自行拼接。确实无法避免进 argv 时必须标记，框架按**值**匹配脱敏——按位置的方案在任何人往命令中间插一个参数时静默失效。

每项探测必须有超时并以结构化状态降级；root 执行时框架自动落一份快照供非 root 读取，消费者**必须**标注来源与时间，快照缺失或过期时明确说明，**禁止**显示过期值而不告知。

替换整份文件**必须**写同目录临时文件再 `mv` 换 inode：`>` 与 `install` 都以 `O_TRUNC` 写原 inode，而 bash 按需分块读脚本，覆盖正在执行的文件会让解释器以 root 执行错乱的字节。模板只从本地随分发目录读取，**禁止**运行时联网取配置。

**脚本安装第三方软件时禁止执行远程 `curl | bash` 安装器**，一律走包管理器或校验 SHA256。唯一例外是按需构建的产物（不存在可事先发布的哈希），须同时满足：官方域名且 HTTPS、下载后做**功能验证**、每次明确告知无校验、另有一条带 SHA256 的来源。走有校验的路时校验失败仍是硬失败，**禁止**因校验不过自动改用无校验来源。

这一条约束的是**本工具去装别人的东西**。用户安装 OneServer 自身是另一回事：`curl … | bash install.sh` 是官方入口，它就是信任根的起点，此前不存在任何可用来校验它的东西。`install.sh` 拿到清单之后照常校验每个文件的 SHA256，并且必须诚实说明这提供的是完整性而非真实性（§13）——它已经这么写了，不要在文档或输出里把它说成「已验证来源」。

## 12 · state 与卸载

state 是行式的"组件标识 + 键 + 值"三元组，原子写并保留上一版；损坏时逐行恢复，整份不可读时回退备份，两者都坏进入降级模式并明确告知卸载不可靠。**不用 JSON**：全有或全无的格式末尾少一个括号就整份报废，且校验它需要 `jq`。**state 记录系统事实，不记录本次调用意图。**

声明 `@provides` 的脚本成功后必须写入完整组件标识。安装类**必须登记本组件创建的资源**：`pkg`（只登记本次真正装上且属于本组件的，通用依赖不登记）、`file`（只登记本项目创建的，改过一行的既有配置不算）、`divert`、`alt`；`unit` 由框架自动登记。

框架不自动攒 `file`：它分不清"我新建的"与"我改了一行的既有配置"，后者被当前者登记会删掉包自带的配置甚至用户手写的东西。这个判断只有脚本作者做得了。

**卸载只读清单并逆序反向执行**：停用 unit → 移除 alt → 撤销 divert → 删除 file → purge pkg → 按命名空间清凭据。顺序不可调换：先删 file 再移 alt 会留下断链，先 purge 再撤 divert 会留下谁也管不到的孤儿。凭据最后清，因为卸载过程本身可能要用它们。

**永不自动删除**，只打印位置由用户处置：用户配置、数据与证书、数据库、站点目录、备份。

## 13 · 分发与更新

`manifest.txt` 是分发物的**唯一**清单，由生成器产出、不入库，**禁止**在任何地方另写一份文件清单。行式、制表符分隔、字段数固定禁止空字段（空字段会让后面的字段整体左移）、路径禁止空白与 `..`、权限取自 git 索引模式、未知行前缀忽略并告警（这就是"加字段不破坏老客户端"的实质）。

**SHA256 提供的是完整性，不是真实性**——manifest 与被它校验的文件来自同一个仓库、同一条 TLS 连接。**禁止**在文档或输出里把它说成"已验证来源"。

更新固定为四阶段：下载到 staging → 校验 → 取锁；把切换器**复制到 `$OS_ROOT` 之外一个可执行的临时目录**（§4.2 的 `/var/tmp/oneserver`，经 `os::tmpdir --exec`）再 `exec` 它；切换器原子切换目录并**以子进程**跑新版本自检；自检失败就地回滚并以非零码退出。

**落脚点不能是 `/run`**：systemd 给它挂 `noexec`（Debian 13 与 Ubuntu 24.04 实测都是），复制过去、给了执行位，`exec` 仍然 `Permission denied`——更新在两个受支持的发行版上都走不完，而更新通道正是所有安全修复的投递路径。本节一度与 §4.2 的落点表相互矛盾，以 §4.2 为准。清理放在下一次准备切换器之前，不放在用完之后：本进程随后就 `exec` 走了，退出钩子不会跑。

**切换范围 = 清单覆盖范围**，包括清单里的根级文件（`VERSION`、`install.sh`、`uninstall.sh`），不只是那五个顶层目录。少换任何一样，机器上留下的都是「新 lib 配旧脚本」——而更新命令仍会把它们算进「全部文件校验通过」，报告与事实不符。根卸载器因此必须声明 `@requires_lib`：它 `source` 得到 `lib/`，是 §14 版本闸门的适用对象，缺这一行等于在唯一一个执行 `rm -rf` 与清凭据的脚本上把闸门关掉。

切换器**必须自包含** **[CI]**：不 `source` 任何 `lib/`、不调任何框架函数、不用 `eval`，只用 bash 内建与 coreutils 里最基础的几条（`mv` `cp` `rm` `mkdir` `chown` `chmod` `timeout`）——判据是「不依赖任何一版 `lib/`」，不是「一条外部命令都不许有」。lint 靠文件里的 `# os-contract: updater` 标记认它，换位置时标记跟着走。它要替换的正是自己所在的那棵树，留在原地等于在自己脚下抽地板。中断标记必须保留并在下次运行中提示。

跨版本保留的 `${ROOT}/data` 必须在第一次目录切换前保证为真实目录、`root:root`、0750；创建或校正失败时不得开始切换，回滚代码版本时不删除该运行时数据。

## 14 · 兼容性承诺

破坏下列表面需要主版本号 +1：退出码语义 · JSON 信封字段（只增不减，删字段需 schema +1）· CLI 命令路径（废弃需保留别名一个主版本）· 全局参数语义 · 凭据 key 命名空间格式 · 组件标识语法 · `/etc/oneserver/*.conf` 的 key（**只增不删**）· `manifest.txt` 已有字段（**旧版本必须能读懂新版本的清单**，否则升级路径断在读清单这一步）· 归档目录布局。

`*.conf` 的 key **随它所配的功能存续**：功能本身被移除时 key 一并删除，加载器会明确报「不是已知配置项，已忽略」。留一个设了不生效的 key 不算兼容——用户改了它、什么也没发生、也没人告诉他，那比明确报一句已忽略更糟。

**不是**承诺、可自由变更：`lib/` 内部函数、state 文件格式、日志措辞、`data` 字段内部结构。

`lib/` 有独立于项目版本的 API 版本：新增导出函数或可选参数则次版本 +1，修改签名、删除函数或改变返回语义则主版本 +1，内部实现变更不变。脚本用 `@requires_lib` 声明依赖；校验读的是**正在跑的这份 lib 旁边**的版本文件，不认固定路径——更新过程中新旧两套 lib 会同时存在于磁盘上。

## 16 · 测试与验收

静态检查 `bash tests/lint.sh`，21 项：shellcheck 零告警（zsh 补全另用 `zsh -n`）· shfmt 格式一致 · `disable` 审计（文件内逐条带理由且守棘轮，`.shellcheckrc` 的全局禁用走精确允许列表）· 前端零副作用 · 可执行位与 git 索引一致（该可执行的与不该可执行的都查）· `desc` 固定字符串 · 切换器自包含 · 脚本层调用前缀 · `docs/API.md` 未过期 · 变更流水注释不超阈值（棘轮，只降不升）· 新增或删除公开接口时 `lib/API_VERSION` 必须跟着动 · 规范目录与实际小节一致 · 二级菜单与 dispatch 双向对应 · `root-nolock` 零系统副作用 · 运行时路径不硬编码 · `eval` 零使用且 `sh -c` 脚本文本不含 `${` 展开 · lib 分层与装配 · 脚本文件头 · 元数据自洽 · 公开接口的测试覆盖不倒退（棘轮，只降不升）· 出参函数的局部变量带 `__` 前缀（§10，棘轮，只降不升）。

**候选范围是 git 跟踪的全部 bash 脚本**（`*.sh` `*.bash` `bin/*`），没有豁免名单——需要豁免就说明规则错了，改规则不改范围。但**每一项自有适用面**，因为条款本身就是分层的：`desc`、脚本层前缀只约束 `script/**` 与 `bin/**`；分层只问 `lib/**`；文件头问 `script/**` 与根卸载器；`eval` 不查 `tests/`（检查器自己必然要写出它所检查的那个词）；接口覆盖只搜 `tests/lib/`（lint 的注释里就有接口名，搜整个 `tests/` 会让它们凭注释「被覆盖」）。两个自包含例外不适用「source bootstrap」与路径单一来源，理由是它们根本 `source` 不了 `lib/`。**适用面写在每项检查旁边，与这里必须一致。**

「二级菜单与 dispatch 双向对应」是一条独立要求，不只是检查项：常驻二级菜单的菜单项与 `dispatch` 分支是同一份清单的两处拷贝，靠字符串对上。**两个方向都要守**——菜单有而 dispatch 没有，选中报「未知操作」；dispatch 有而菜单没有，那是一条只有读过源码的人才知道存在的命令。后者要么补进菜单，要么删掉，不该以「没人知道」的状态留着。

`eval` 与接口覆盖两项的范围窄一档，理由写在检查旁：前者只查会落到用户机器上的代码（检查器自己必然要写出它所检查的那个词），后者只搜 `tests/lib/`（lint 的注释里就有接口名，搜整个 `tests/` 会让它们凭注释「被覆盖」）。

注释里**不写变更流水**（"X 是某日移植 Y 时补的"这类）——历史归 git，注释只写此刻仍然成立的理由。存量以棘轮收敛：阈值等于当前条数，只降不升。

单元测试跑在一次性容器里（Debian 13、Ubuntu 24.04、Ubuntu 26.04），本机无 Podman 时转发到测试宿主。**干净容器是首次安装验收的基线**：长期使用的机器会让"尚未安装"这条最容易出错的分支永远得不到覆盖。容器复用宿主机内核，因此足以验证用户态行为，**不足以证明内核相关功能**。

每项功能至少验证：干净环境安装、重复执行幂等、dry-run 零变更、失败可见、权限边界。涉及中断、资源或发行版差异时增加 SIGTERM 后重跑、按清单卸载、双发行版对照。

**只有实际执行过的命令和结果可称"已验证"。** 改动 `lib/` 必须补对应 bats 测试——这条由「公开接口测试覆盖」棘轮执行：阈值记的是当前还有多少个公开接口在 `tests/lib/` 下连名字都搜不到，**只降不升**。

两个自包含例外（`install.sh` 与切换器）同样要有用例。它们没有框架兜底，而它们负责的恰恰是清单解析（输入来自网络，不可信）与原子切换加回滚（失败分支只在「新版本恰好坏了」那一次执行）。

## 17 · 新增或修改脚本

1. 先说明安装、配置、探测、升级/幂等、卸载五项设计，以及安全默认值与用户可选项；获批后再改 `script/**`。
2. 从骨架起手，补全元数据，确认 `@args` 与交互点名字集合相等。
3. 用框架接口实现全部副作用、资源登记、错误与 dry-run 行为。**框架或规范有缺口时先讨论并改本文件，不在代码里绕过。**
4. 对照 §3 不变量逐条自查。
5. 运行与改动风险相称的 lint、单元与容器验收，报告实际命令、输出及未验证项。

新增公开接口时，在函数头首行写 `# <函数名> <参数>   <说明>` 并跑 `make api`——`docs/API.md` 是生成的，缺签名行会被 lint 拦下。

**新发现的缺陷若在本规范中找不到对应条款，说明规范有缺口——先补条款，再修代码。**
